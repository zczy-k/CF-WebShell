# 同步服务部署（全程网页点，不用装任何工具）

这份说明是给**只会用鼠标点网页**的人写的。不用装软件、不用敲命令、不用懂代码。
照着做，从零搭出一个能让多台设备自动同步的中转站。

**做完你会得到**：一个属于你自己的网址，填进软件的「设置 → 同步」里，
电脑加的网站手机上自动就有，删了也一起删。

全程大概 10 分钟（不含等域名生效的时间）。免费，不用绑银行卡。

---

## 开始之前，准备两样东西

**第一样：一个 Cloudflare 账号。**

打开 https://dash.cloudflare.com/sign-up ，用邮箱注册一个，免费。

**第二样：两份现成的文本文件。**

不用你写，项目里已经放好了，直接复制：

| 文件 | 干嘛用 | 直接打开这个网址复制 |
| --- | --- | --- |
| `schema-plain.sql` | 建表（纯 SQL，**一行注释都没有**，粘进网页控制台不会报错） | https://raw.githubusercontent.com/zczy-k/Starport/main/worker-sync/schema-plain.sql |
| `index.js` | 程序本体（真正的同步逻辑） | https://raw.githubusercontent.com/zczy-k/Starport/main/worker-sync/src/index.js |

打开上面两个网址，看到纯文字后按 `Ctrl+A` 全选、`Ctrl+C` 复制，先放着待会粘。

> 这两个链接是公开只读的，复制不会改动任何东西。
>
> ⚠️ `schema-plain.sql` 刚改过（去掉了文件头那几行 `--` 注释）。
> 如果你打开链接还看到 `--` 开头的字，是 GitHub 的缓存没刷新 ——
> 在网址末尾加个 `?v=2` 再打开，或者等几分钟再试。
> **正确文件打开后第一行就是 `CREATE TABLE`，一个 `--` 都没有。**

---

## 第 1 步：建一个数据库（装数据的"仓库"）

登录 Cloudflare 后，在左侧菜单找：

```
Storage & Databases  →  D1 SQL Database  →  Create database
```

> 菜单是英文的。找不到就用页面顶部的搜索框搜 `D1`。

- **Database name**（数据库名字）填：`starport-sync`
- 点 **Create**

✅ **做完你会看到**：列表里多了一个叫 `starport-sync` 的库，点进去有个 **Console**（控制台）标签。

---

## 第 2 步：建表（把刚复制的 SQL 粘进去）

点开刚建好的那个库 → 切到 **Console**（控制台）标签。

> ⚠️ 一定是 **Console / 控制台**这个标签，不是「概览」也不是「查询数据」。
> 概览页只有数字，没有输入框，你在那粘什么都不会发生。

**先把鼠标点进那个输入框**（点一下，看到光标在闪），`Ctrl+A` 全选、`Ctrl+C` 复制
前面准备好的 `schema-plain.sql`，`Ctrl+V` 粘进去，最后点 **Execute / 执行**。

> 粘进去之后，输入框里**第一行就应该是 `CREATE TABLE`**，一个 `--` 都不该有。
> 如果你看到 `--` 开头的字，说明粘错文件了 —— 那份叫 `schema.sql`（带中文说明的），
> 网页控制台读不了那些说明，会报 `No SQL statements detected.`。
> 要用的是 `schema-plain.sql`，这份只有 8 行纯 SQL。

✅ **做完你会看到**：下面出来一片执行结果，没有红色报错。

切回 **概览** 标签（或刷新一下），**表数量**应该变成 **5**：

```
spaces    devices    pair_codes    space_history    rate
```

> 这几张表就是同步的全部家当。少一张也没关系，只要没报错就行。

**如果提示 `No SQL statements detected.`**（没读到任何语句）：

1. 确认你点的是「库 → 控制台」那个**带输入框**的标签，不是概览页
2. 粘完先别急着点执行，抬眼看输入框里有没有 `CREATE TABLE` 字样；空的就重新点一下输入框再粘
3. 还是不行，就把 `schema-plain.sql` 里那 8 条语句**一条一条单独粘、单独执行**，8 次点完也是 5 张表

---

## 第 3 步：建程序（Worker）

左侧菜单：

```
Workers & Pages  →  Create  →  Workers  →  Create Worker
```

- 名字填：`starport-sync`（叫别的也行，**网址跟这个名字没关系**）
- 点 **Deploy**

✅ **做完你会看到**：一个写着 "Hello World" 的默认页面，别管它，下一步就把它换掉。

---

## 第 4 步：换成真正的程序

在那个 Hello World 页面上，点右上角 **Edit code**（编辑代码）。

1. 在代码框里 `Ctrl+A` 全选、`Delete` 删干净
2. 把前面复制好的 `index.js` **全部内容**粘进去
3. 点右上角 **Deploy**

✅ **做完你会看到**：提示部署成功。

---

## 第 5 步：把程序和数据库接上（最容易漏的一步）

漏了这一步，所有请求都会报错。

回到这个 Worker 的页面 → **Settings**（设置）→ 找到 **Bindings**（绑定）→ **Add** → 选 **D1 database**

- **Variable name**（变量名）填：`DB` ← **必须正好是大写 `DB`，填别的程序找不到数据库**
- **D1 database** 选第 1 步建的那个 `starport-sync`
- 点 **Save / Deploy** 保存

✅ **做完你会看到**：Bindings 列表里多了一行，名字叫 `DB`。

---

## 第 6 步：设一个"门锁密码"

这个密码决定**只有你能开启同步空间**。别人就算知道了你的网址，没有它也接不进来。

同一个页面的 **Settings** → **Variables and Secrets** → **Add**

- **Type**（类型）选 **Secret** ← ⚠️ 千万别选 Text，选错了密码会明文显示出来
- **Variable name** 填：`BOOTSTRAP_SECRET`
- **Value** 填一串你自己编的随机字符，**至少 40 位**

> **怎么弄一串够乱的？** 随便敲键盘，别用生日、手机号、`123456` 这种。
> 例子：`kR7pXq2mWz9vTn4bLs8dYf6hJc3gVa5uNe1oQi0tMrPx`
>
> **这串丢了怎么办？** 重新设一次就行，已经配好的设备不受影响 ——
> 它只在「第一次开启同步空间」的时候用那么一次。

点 **Add / 保存**。

✅ **做完你会看到**：Variables and Secrets 列表里有一行叫 `BOOTSTRAP_SECRET`，类型是 Secret，值显示为隐藏。

**到这里，需要你手动填的东西已经全部填完了。** 后面只剩挂域名和在软件里用。

> 你可能会注意到设置页里没有别的配置项 —— 这是对的。
> 程序内部有几个调节用的数字（比如历史版本留几版、每小时最多推几次），
> 它们都有默认值，不填照样跑。想改的话看文末「网页上怎么改这些数字」，
> 部署阶段完全不用管。

---

## 第 7 步：拿网址 —— 挂一个自己的域名

Worker 页面上会显示一个 `https://xxx.workers.dev` 的网址，**别用它**：
这个域名在国内基本打不开（一直转圈、超时、连接被重置）。
要挂一个你自己的域名才能正常用。

需要什么：**一个自己的域名**，任何注册商买的都行，一年几十块。
服务器在境外（Cloudflare 的边缘节点），所以**不需要备案**。

1. **把域名加进 Cloudflare**：控制台首页 → **Add a site** → 填你的域名 → 选 **Free** 计划
2. **去买域名的网站改 NS**：Cloudflare 会给你两个地址（形如 `xxx.ns.cloudflare.com`），
   到买域名那家的「DNS / 域名服务器」设置里，把原来的两个 NS 换成这两个
3. **等生效**：几分钟到 24 小时不等。Cloudflare 上那个域名从 `Pending` 变成 **Active** 就好了
4. **回 Worker 挂域名**：你的 Worker → **Settings** → **Domains & Routes** → **Add** →
   选 **Custom domain** → 填一个子域名，比如 `sync.你的域名.com`
5. **等证书**：一般 1~3 分钟，域名旁边出现一把锁就好了

**这个 `https://sync.你的域名.com` 就是软件里要填的「服务地址」。**

先验一下服务是不是活的 —— 浏览器新开一个标签，访问：

```
https://sync.你的域名.com/v1/health
```

✅ **应该看到**：`{"ok":true,"service":"starport-sync","schema":1}`

看到这一行就说明成功了。看到别的（尤其 404 或 500），先别往下走，翻到最后的「出问题怎么办」。

> **建议先把域名挂好，再去软件里开启同步** —— 省得配好一堆设备后还得回头改地址。
> 以后换域名**不用重新配对，也不用重新开同步空间**，改完地址同步状态会自己刷新一次。

---

## 第 8 步：在软件里开启

1. 打开软件 → **设置** → **同步**
2. **服务地址**：填第 7 步那个网址（`https://sync.你的域名.com`，**末尾不要带斜杠 `/`**）
3. **部署密钥**：填第 6 步那串随机字符
4. 点 **「开启同步（本机作为第一台设备）」**

✅ **做完你会看到**：状态变成「已上传本机改动」，下面显示上次同步时间。

---

## 第 9 步：第二台设备接进来

在**已经同步好的那台**设备上：

```
设置 → 同步 → 显示配对码
```

会出来一组 **8 位码**，10 分钟内有效、只能用一次。

在**新设备**上：

```
设置 → 同步 → 服务地址填同一个网址 → 用配对码加入 → 填那 8 位码
```

✅ **做完你会看到**：两台设备的站点列表变成一样。

之后不管在哪台设备上加站、删站、改设置，另一台几十秒内都会自己跟上。
**设备数量不限**，配对过的都能连。

## 出问题怎么办

先看这个表，八成能对上：

| 你看到的 | 原因 | 怎么办 |
| --- | --- | --- |
| 建表时提示 `No SQL statements detected.` | 控制台没读到语句（粘错地方 / 没粘全） | 见第 2 步下面那一小节，一条一条粘 |
| 概览里「表数量」还是 0 | 建表没真执行成功 | 回第 2 步重做，确认执行后有一片结果输出 |
| `/v1/health` 一直转圈、超时、连接被重置 | 还在用 `workers.dev`，或域名证书没签好 | 按第 7 步挂自己的域名，等域名旁边出现锁 |
| 域名挂了还是打不开 | NS 还没生效，或子域名填错 | 域名的状态要变成 **Active**；检查挂的是 `sync.你的域名.com` 这种完整子域名 |
| `/v1/health` 返回 500，写着 `no such table` | 第 2 步没做，或做在了别的库上 | 回去重做第 2 步，确认是在那个 D1 库的 Console 里执行的 |
| `/v1/health` 返回 500，别的错 | 第 5 步的绑定没加，或变量名不是 `DB` | 检查 Bindings 里是不是正好有一行叫 `DB` |
| 软件里点开启，提示「密钥不对」 | 第 6 步的名字打错了 | 变量名必须正好是 `BOOTSTRAP_SECRET`，全大写 |
| 软件里点开启，提示「连不上」 | 网址填错，或末尾多了斜杠 | 只填域名本身，形如 `https://sync.你的域名.com`，末尾不带 `/` |
| 第二台设备配对码说「过期」 | 配对码只有 10 分钟 | 在那台设备上重新点一次「显示配对码」 |
| 同步了但站点没变 | 还在排队（最多几十秒） | 点一下「立即同步」按钮 |
| 突然所有站点都没了 | 触发了「大面积删除」保护 | 见下面 |

### 关于「检测到一次大量删除」

如果一次同步会让这台设备少掉一半以上的站点，程序会**停下来等你确认**，不会直接执行。
设置页会出现一条黄色警告，两个按钮：

- **确认删除 N 个** —— 确实是你自己在另一台设备上删的，点这个
- **恢复上一版** —— 不是你干的，点这个退回之前某一版

这是故意设计的。同步最怕的不是"没同步上"，是"同步错了把你的东西删光"。

### 都不对劲

把下面三样贴给开发者，能省很多来回：

1. `/v1/health` 打出来的原文
2. 软件里「同步」那块显示的完整状态文字
3. Cloudflare 后台 → 你的 Worker → **Logs**（日志）里最近几条

## 网页上怎么改那些数字（可选，部署时用不上）

程序里有几个可以调的数字，都有默认值，**不设置照样跑**。
想改的话：Worker → **Settings** → **Variables and Secrets** → **Add**，
类型选 **Text**（不是 Secret），名字和值按下表填，加完重新 Deploy 一次才生效。

| 名字 | 默认值 | 意思 |
| --- | --- | --- |
| `MAX_DOC_BYTES` | `524288` | 一份站点清单最大多大（字节） |
| `RATE_WRITES_PER_HOUR` | `60` | 每台设备每小时最多推几次 |
| `RATE_SPACE_PER_HOUR` | `2000` | 所有设备加起来每小时最多几次 |
| `MAX_DEVICES` | `0` | 最多几台设备，`0` = 不限 |
| `PAIR_TTL_SECONDS` | `600` | 配对码几分钟有效 |
| `HISTORY_KEEP` | `20` | 云端历史版本留几版 |
| `HISTORY_TTL_DAYS` | `7` | 云端历史版本留几天 |
